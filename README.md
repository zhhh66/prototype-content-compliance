# 原型内容合规检查（Prototype Content Compliance）

一款 WorkBuddy 自定义技能：对照**产品原始需求文档 / PRD**，审计 AI 生成的 **HTML 原型 / UI 原型 / 设计稿**，识别 AI 自行"脑补"、需求中并不存在的页面内容（字段、副标题、标签、说明文字、无意义重复展示），防止多余内容流入 UI 造成设计返工。

> 触发命令：`/原型内容合规检查`

## ✨ 功能特性

- **客观比对，不自由发挥**：只做"需求文档 vs 原型 DOM"的逐项对比，不擅自解读或改写业务需求。
- **三类风险筛查**：
  1. 需求不存在、AI 凭空新增的字段 / 副标题 / 标签 / 辅助描述 / 模块；
  2. 无合理业务逻辑、同一数据在多处重复展示；
  3. 卡片需求仅主标题，AI 额外增加副标题、说明文字。
- **可选自动清理**：默认只出风险清单，由产品人工确认取舍；确认后追加 `--apply` 输出清理后的完整 HTML。
- **复杂场景覆盖**：多层级 / 嵌套页面、动态渲染（JS/AJAX）、组件复用、条件渲染（A/B/灰度）、通用第三方模块。
- **进阶配置**：`--strict` / `--ignore` / `--depth` / `--lang` / `--dynamic` 等可选参数微调审计范围。

## 📦 安装方式

### 方式一：WorkBuddy 导入（推荐）
1. 下载本仓库（或 `SKILL.md` 单文件）；
2. 在 WorkBuddy 技能管理中选择「导入技能」，上传 `SKILL.md` 即可一键安装。

### 方式二：SkillHub 市场
已在 SkillHub 上架，搜索「原型内容合规检查」直接安装。

### 方式三：手动放置
将本目录（含 `SKILL.md`）放到 WorkBuddy 的 skills 目录下：
```
~/.workbuddy/skills/prototype-content-compliance/
```

## 🚀 使用方式

### 输入模板
```
【原始产品需求】
粘贴你的需求 markdown（页面有哪些模块、允许哪些字段、主标题叫什么）

【HTML原型代码】
粘贴 AI 生成的完整 HTML

可选追加参数：--apply
```

### 进阶参数
| 参数 | 作用 |
|------|------|
| `--apply` | 输出清理后的完整 HTML（仅移除无争议脑补元素） |
| `--strict` | 严格模式：把"需求未明确禁止但存疑"的内容也标为风险 |
| `--ignore=<关键词或CSS选择器>` | 忽略清单，如 `--ignore=页脚,备案号` |
| `--depth=N` | 限定 DOM 嵌套扫描深度，大型页提速 |
| `--lang=zh\|en` | 报告语言，默认中文 |
| `--dynamic` | 动态内容模式：提示将渲染后 HTML 或数据绑定清单一并粘贴 |

复杂场景示例：
```
/原型内容合规检查 --depth=5 --ignore=页脚,备案号 --dynamic
```

## 📝 使用示例

**需求**
```markdown
页面：用户信息卡片
- 模块：用户信息区
- 允许字段：头像、昵称、会员等级
- 展示数据：仅上述三个字段
- 标题结构：卡片主标题固定为"用户信息"
```

**原型（含 AI 脑补元素）**
```html
<div class="card">
  <h3>用户信息</h3>
  <img src="avatar.png" alt="头像">
  <span>小明</span>
  <span class="level">VIP3</span>
  <p class="subtitle">欢迎回来，尊贵的用户</p>
  <span class="tag">热门</span>
</div>
```

**审计报告（节选）**
```
# HTML原型内容审计报告
## 1. 风险清单
- 【风险】.card > p.subtitle：需求无此字段，AI凭空新增【副标题"欢迎回来，尊贵的用户"】
- 【风险】.card > span.tag：需求无此标签，AI凭空新增【标签"热门"】
```

## ⚠️ 注意事项
- 自动清理（`--apply`）仅作为可选功能，业务内容存在不确定性，**默认只提供清单，由产品人工确认取舍**。
- 本技能只校验"内容是否合规"，**不校验颜色、圆角、边框等视觉样式**（样式规范交给样式审计技能）。
